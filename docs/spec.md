## Overview

Where To Park is a mobile app for drivers in the Philippines to find parking with open space near them, and for Operators (from commercial lots to residents with vacant driveways) to publish their spaces, live availability, and rates, and to run day-to-day parking operations (walk-ins, chat, reservations, cash collection).

### Key Facts

- **Problem**: Drivers circle around not knowing which lots have space, fit their vehicle, or what they cost; Baguio's tight streets and tourist peaks make it worse.
- **Beta Market**: Baguio City
- **First Release Goal** (Phase 1, Android): Operators list spaces with photos, Monthly rates and a live slot count; drivers search on a map with a results sheet, sort and filter, see ETAs, navigate, read reviews and chat; staff run walk-in sessions paid in cash with the ledger, fees, overdue handling and chat.
- **Currency**: PHP (pesos, numeric(12,2))
- **Dimensions**: Centimeters
- **Language**: English only for now
- **Platforms**: Android first; web for preview; iOS deferred

## Architecture

- **App**: Expo (React Native + TypeScript), Expo Router; 🟧 Expo SDK 54 (React Native 0.81, React 19.1, New Architecture; Android edge-to-edge)
- **Backend**: Supabase (Postgres + PostGIS, Auth, Realtime, Storage, RPCs/Edge Functions)
- **Maps**: MapLibre (native: 🟧 @maplibre/maplibre-react-native v11, web: maplibre-gl) on OpenFreeMap OSM tiles
- **Geocoding**: Photon (search-as-you-type), Nominatim (≤1 req/s, cached, with User-Agent)
- **Routing**: OpenRouteService Matrix API for drive-time ETAs (via Edge Function, cached, rate-limit aware, with straight-line fallback)
- **Payments (Phase 4)**: PayMongo (GCash), generic PaymentGateway interface
- **Principles**: API-first (every action is a documented RPC/Edge Function), cash-first, defaults tuned for hourly rates and slot counts, free map stack, one locked code path for every capacity change

## Core Features (Phase 1)

### F1. Operators, Locations, Areas, Availability

- Operators list spaces (commercial or residential) with exact map pin, address, optional rules
- Upload photo gallery (up to 10, reorder, pick cover; Storage)
- 🟧 **Photo viewer (ImageCarousel)**: Tapping a listing photo on the details page opens a floating full-screen viewer (modal overlay, dark backdrop) at that photo. Swipe left/right between photos (‹ › buttons too, mainly for the web), ✕ (or Android Back) closes it, and the top shows the position, e.g. '2/5'. It is one reusable component (`src/components/ImageCarousel.tsx`), also used for review photos and the Photos tab
- 🟧 **Photo collection**: A listing's photos are its operator photos plus the photos attached to its reviews. The collection is derived, not copied: the `listing_photo_collection` view (security_invoker, so the tables' RLS applies) unions `location_photos` and `review_photos` (via their review), ordered operator photos first (cover first, then sort order), then review photos oldest first. A review photo leaves the collection as soon as it or its review is deleted, or the review is hidden. The details gallery strip and its viewer show the whole collection; review photos carry a small 'From a review' tag on the strip and in the viewer. If the view can't be read (e.g. a database without migration 0037) the page shows the operator photos only. Migration 0037 (staging; prod later)
- Name areas inside a location (B2, Left Wing) to group slots/rates
- 🟧 **Areas and Rates are two pages**: The listing page (hub) has separate **Areas** and **Rates** buttons instead of one 'Areas and rates'. **Areas** (header 'Areas') lists the listing's areas with Delete and has the 'New area name' field and **Add area**. 🟧 Delete asks first: a dialog 'Delete '<area>'?' ('This removes the area from <listing>.') with a red **Delete** and **Cancel** (same dialog look as the listing delete, without the slider); the area is only removed after Delete. **Rates** (header 'Rates') has the price preview, the rate list (Edit / Delete, default locked) and the new/edit rate form. 🟧 **Rate form on its own page**: the Rates page now has the price preview, the rate list and an **Add rate** button; **Add rate** opens **New rate** and a row's **Edit** opens **Edit rate** (own page, header 'New rate' / 'Edit rate', Back to the Rates list, also without history). **Create rate** / **Save rate** returns to the Rates list, which reloads and shows the change (and the preview refreshes). Effective dates are Asia/Manila days and 'Effective to' is inclusive (the rate runs to the end of that day); editing shows the same days that were saved (before, they read back one day early). Editing a rate keeps what the form doesn't show (area, max per day, active, default) instead of clearing it. 🟧 **Days of week**: the New/Edit rate form has day chips (Mon … Sun); none selected means every day. Each row on the Rates list shows its days ('Sat, Sun', or 'Every day'). Days count in Asia/Manila and apply to the day the stay starts (see Price preview); saved with `upsert_rate` (`p_days_of_week`, migration 0041). 🟧 **Vehicle**: the New/Edit rate form has an optional vehicle choice (All vehicles, Car, SUV, Van, Motorcycle, Truck; All vehicles = empty = any vehicle), and each Rates row shows it ('SUV' or 'All vehicles'). Saved with `upsert_rate` (`p_vehicle_type`, migration 0044). A vehicle-specific rate only prices that vehicle; this also applies to the default when it is the last-resort fallback (a car-only default doesn't price a motorcycle) 🟧 **Set as default**: each rate that can be the default shows a **Set as default** button; tapping it makes that rate the listing's default and the old default becomes a normal rate in the same server step (`set_default_rate`, migration 0039; a listing can never have two defaults, enforced by a unique index). The default stays undeletable ('Default (locked)'), but which rate is default can change. 🟧 The default rate's row has no Delete button at all (no 'Default (locked)' control); the server still refuses deleting it, and rate errors now show plain messages ('The default rate can't be deleted. Make another rate the default first, then delete this one.', 'Only the listing owner or a manager can change rates.', …) instead of codes. Monthly rates, rates with effective dates and inactive rates can't be the default (the default prices any hour no other rate covers, so a monthly default would quote ₱0). 🟧 **Revised (migration 0042)**: any rate type can be the default, monthly included, but the default applies every day with no dates: it can't have effective dates or days of week (enforced by a check constraint, `set_default_rate` and `upsert_rate`), and it must be active. 'Set as default' is offered only for active rates without dates or days; editing the default hides the date and day fields with the note 'The default rate applies every day, with no dates.' **Pricing with a monthly default**: monthly rates never price a stay, so the listing's other matching hourly/daily/flat rates price it; if none match, the preview says 'No rate covers this stay. Monthly rates never price a stay, so add an hourly, daily or flat rate for this time.', and a walk-in still starts (billed ₱0 until staff add a charge). Only owners/managers can do it (same rule as editing rates); staff don't see the Rates page and the server refuses them. Both show the listing name at the top and Back to the listing page (also without history). The onboarding note now says 'You can add more rates later under Rates'
- Invite staff and assign them to locations
- Update availability in one tap: +1/-1, or mark Reserved/Unavailable

**Key Points:**

- Map pin picker with address search; stored as PostGIS geography(Point). 🟧 Tapping the map moves the pin and the form saves it (no 'Use this pin' button, no coordinates text; the hint 'Tap the map to drop the pin' stays). On **Edit listing** only, once the pin is moved away from the listing's saved position, a small round ↺ button (accessibility label 'Restore saved pin') shows in the map's top-left corner; tapping it puts the pin back on the saved position and recentres the map, and it hides again while the pin is on the saved position. After **Save**, the new position becomes the saved one. Onboarding (new listing) has no saved position, so no restore button
- Last status/count and 'updated X ago' always show; past Operator threshold (default 2h) styled as warning (e.g. amber)
- New listings publish as 'Unverified'; admins notified and verify after review
- Manual Reserved/Unavailable changes go through `claim_capacity` (same locked path as check-ins/reservations)
- 🟪 **Deleting a listing (app)**: The listing hub (My listings → a listing) shows a red **Delete listing** button at the bottom, for the operator's **owner** only (managers and staff don't see it). It opens a dialog that explains what deleting does, with a **Slide to delete** control and **Cancel**. Sliding to the end calls `delete_location`. If the listing still has active sessions or reservations, the dialog says so with the counts ('This listing still has 1 active parking session and 1 active reservation. End every active session and cancel every active reservation first, then try again.') and offers **Open the session board** for that listing (there is no reservations screen yet; Phase 3). On success the app goes to My listings and shows a green toast ''<name>' was deleted'. A deleted listing is gone from search, the map, My listings and the admin queue; opening it from an old link shows 'Listing not found' (details page and listing hub)
- 🟪 **Deleting a listing (server)**: `delete_location(p_location_id)` (SECURITY DEFINER, signed-in only). Only the operator's **owner** may delete (managers and staff get 'forbidden'). It takes the same row lock as `claim_capacity`, so it can't race a check-in, then refuses with `has_active` plus `active_sessions` / `active_reservations` counts while any session isn't ended or any reservation isn't finished (completed, cancelled, declined, expired, no-show; any other or future status counts as active). It is a **soft delete**: `deleted_at`/`deleted_by` are set and the listing is unpublished, but the row stays so sessions, folios, payments, reviews and chat keep their references. Deleted listings are left out of `search_nearby`, `get_etas`, the admin queue count and the My listings count in `get_sidebar_counts`, and the public read policy; `claim_capacity` refuses them (no new check-ins or reservations); owners/managers can't edit or un-delete them through the API. Operator members can still read the row, so names in their session and chat history still show

- 🟧 **Shortcuts (migration 0053)**: Location details shows a **☆ Add shortcut** chip under the availability badge (header area, all tabs; no top nav row). Tapping it adds the listing ('Added to Shortcuts in the menu') and the chip becomes **★ Remove shortcut**. The sidebar shows a **Shortcuts** section (only when there is at least one shortcut) listing the **first 3** in order, each opening that listing's details, with a **View all** link beside the title that opens the **Shortcuts** screen (header 'Shortcuts'; Back falls back to Search). The screen lists **all** shortcuts in the user's order (new ones are added at the **bottom**); **hold a row (~0.3 s) and drag** to reorder (others shift to show where it lands; saved on release), and **Delete** asks first (**Delete** / **Keep**). No limit on how many. Signed-in users' shortcuts are stored per account in `location_shortcuts` (user, listing, position; one per listing; owner-only RLS; `add_location_shortcut` appends, `reorder_location_shortcuts` saves the order); **guests** keep theirs on the device (local storage) and 🟧 when a guest who has shortcuts on the device signs in, a dialog asks once: **'Add your N shortcuts from this device to your account?'** with **Add** / **Don't add** (N = the device shortcuts the account doesn't have yet). **Add** appends those to the bottom of the account's list in device order (listings deleted meanwhile are skipped). Either way the device list is **kept** for when they're signed out, and the answered set is remembered on the device, so the same set isn't offered again (adding a new one as a guest makes the set new, and the next sign-in asks about the ones the account lacks). Nothing is asked when the account already has them all. A shortcut to a listing that was deleted or is no longer visible stays in the list as '<name> (no longer available)' (greyed) and can be deleted; opening it shows 'Listing not found'; deleting a listing removes everyone's shortcuts to it.

- 🟧 **Manage listing from Location details**: next to **Add shortcut**, users who manage that listing (the operator's owners and managers, and staff assigned to it) also see **⚙ Manage listing**, which opens that listing's operator page (`/operator/hub/<id>`, header = listing name). Staff land on the staff view there (Active Sessions, Check In and the rest they can access). Everyone else (drivers, guests, staff of other listings) doesn't see it. The role is read client-side from the user's `operator_members` rows (same rule as My listings); the hub still checks access itself.

### F2. Parking Rates

- One default rate per location (editable, not deletable)
- 🟧 **The default rate is always applicable (migration 0047)**: the default applies to **every vehicle, every day, with no dates, area or spot**, and is always active, so it is always in the check-in rate list and can always price a session (any rate type, monthly included). The New/Edit rate form hides the Vehicle choice when editing the default (note: 'The default rate applies to every vehicle, every day, with no dates…'); **Set as default** is offered only on active all-vehicle rates without dates, days, area or spot; the server refuses the rest (`default_cannot_have_vehicle`, `default_cannot_have_area`, plus the 0042 date/day rules) and a check constraint backs it. Existing defaults with a vehicle or area were cleared to all vehicles / no area (none on staging). **Every listing always has a default**: `create_location` (used by onboarding) creates the listing and its 'Standard Rate' default in one transaction, the RPCs refuse deleting or unsetting the default, and deferred database checks refuse, at commit, any write that would leave a listing without a default (including direct table writes); deleting a listing still takes its rates with it. Staging: all 13 listings have a default.
- 🟧 **Deactivate, activate and archive rates (migration 0048)**: Each non-default rate on the Rates screen has **Deactivate**; an inactive rate shows an **Inactive** badge with **Activate** and **Archive** (Edit stays). Inactive rates show only on the Rates screen: they're never applicable at check-in, in the rate dropdown, in automatic pricing, in the price preview or in session edits, and the server refuses them for new and edited sessions (`rate_not_applicable`); the driver listing page shows active rates only. **Deactivating is refused while any open session (active/overdue, started or upcoming) uses that rate** (🟧 0050, rj: 'any session that uses the rate blocks deactivating it'), with the count ('2 open sessions (active or upcoming) use this rate, chosen or on Automatic. End them or pick another rate for them, then deactivate.', shown on that rate's row); a database trigger backs this for any write. (🟧 0054 supersedes the rest of this sentence: only sessions whose set rate is that rate block it.) A session **uses** a rate when the rate is its chosen rate, or when the session is on **Automatic** and the rate could price some part of its span: the rate is for all vehicles or the session's vehicle; it has no spot/area or the session's spot/area; its dates overlap the span (start → billed or planned End, or start → forever when there's no End); and it has no days, or the span (within the rate's dates) touches a Philippine calendar day on one of its weekdays (a span of 7+ days or with no End always does). Monthly rates count too. So an open-ended Automatic session blocks deactivating every rate that matches its vehicle and spot and isn't dated entirely before its start. **Archive** (inactive rates only, after a confirm: 'Archive …? It disappears from this list and can't be used again. Past sessions keep it.') is a soft delete (`archived_at`): hidden from the Rates screen, kept for past sessions and history; an archived rate can't be re-activated directly. 🟧 **Restore (0051)**: **Show archived** at the bottom of the Rates screen lists the listing's archived rates (newest first, 'archived <date>'), each with **Restore**; a restored rate comes back to the list **inactive** ('… restored (inactive). Activate it to use it again.') and can then be activated, edited or archived again (`unarchive_rate`, owners/managers only). **Archive replaces Delete** in the app: sessions now store their rate (0045), so `delete_rate` refuses any rate a session references (`rate_has_sessions`). The default can't be deactivated, archived or deleted (`cannot_deactivate_default`, `cannot_archive_default`, `cannot_delete_default`). Owners/managers only (`set_rate_active`, `archive_rate`).
- Custom rates with any name, optional effective period, optional scope (area/slot/vehicle/days)
- Monthly rate alongside Hourly/Daily so drivers can filter by Monthly
- Rate preview tool shows which rate wins and why
- 🟧 The rate preview (🟧 now the Rates screen) asks for a quote only when a listing is picked; opened without one it just shows 'Pick a listing from My listings' (before, it still called `quote_price` without a listing, got a 404 and showed that error instead).
- 🟧 **Price preview with a date**: The preview asks for a **Date** (YYYY-MM-DD, default today) and a **Start time** (HH:MM, 24-hour, default now), both Asia/Manila, plus **Hours**, and quotes a car stay starting then ('Car, starting Sat, Nov 7, 2026 10:00'). 🟧 It also has a **Vehicle** choice (Car, SUV, Van, Motorcycle, Truck; default Car), passed to quote_price, so vehicle-type rates apply ('SUV, starting …'). Day-of-week limited rates apply when the stay starts on one of their days, and dated rates when the start falls inside their dates (Effective to is inclusive). Rate choice (quote_price, migration 0040): dated rates first, then slot > area > vehicle type > day-limited > default > other, then priority and newest; if nothing matches, the active non-monthly default. **The rate in effect when the stay starts prices the whole stay**, even if it runs past midnight into another day or past a rate's end date (the preview says so). Bad input (date, time, hours ≤ 0 or not a number) shows a message in the preview instead of quoting 1 hour; a server error clears the old amount and shows in the preview. Fixed: day-of-week limits were ignored (SM City's Weekend Rate never applied), a day-limited rate lost to the default, a rate with only 'Effective to' wasn't treated as dated, the default fallback could pick an inactive or monthly rate, and the preview always quoted 'now'. The same quote_price prices walk-in sessions, so they get the same fixes 🟧 **Split across rates (migration 0043; replaces 'the rate in effect when the stay starts prices the whole stay')**: a stay is billed in started hours (billed hours = hours rounded up, at least 1) and **each billed hour is priced at the rate in effect when that hour starts** (same rate choice as above, checked per hour; day-of-week in Asia/Manila). Each rate is then charged for its own hours as if they were one stay: hourly × hours; daily × started 24 h of its hours; flat-then-hourly charges its flat amount once for its first hours, then its hourly amount; **max per day caps each rate separately** at max × started 24 h of that rate's hours. Example: Sunday 22:00 for 4 h with Weekend ₱60/h (Sat, Sun) and the weekday ₱40/h default = 2 h × ₱60 + 2 h × ₱40 = **₱200**; an hour starting at exactly 00:00 belongs to the new day. Entering or leaving a dated rate splits the same way. If any hour has no rate, the quote fails ('No rate covers this stay…', with 'Not covered from Mon 00:00.'). The preview shows the total and, when more than one rate applies, one line per rate ('Weekend Rate: 2h from Sun 22:00 · ₱120.00'); its note now reads 'Each hour is priced at the rate in effect when that hour starts…'. Walk-ins (start_walk_in) and live/closing balances (session_parking_quote) use the same quote_price. Overnight or other extra charges are not automatic: staff add them on the session as fees (Fee presets / additional charges, `apply_fee_preset`), on top of the split parking amount. SQL tests: `supabase/tests/quote_price_split.sql`

**Rate Types:**

| Type                            | Operator Enters                            | Charged                                                                                                                                                                                                                                                |
| ------------------------------- | ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Hourly (default)                | ₱ per hour                                 | Per started hour, minimum 1 hour                                                                                                                                                                                                                       |
| Daily                           | ₱ per day                                  | Per started 24h from check-in                                                                                                                                                                                                                          |
| Flat first N hours, then hourly | N hours, ₱ for them, ₱ per succeeding hour | Flat amount covers first N hours, then per started hour                                                                                                                                                                                                |
| Monthly                         | ₱ per month                                | Shown on listing and used by Monthly filter. 🟧 Prices a walk-in session only when it is the session's rate (chosen, or Automatic when only monthly rates apply): per started month from the start (0045); the price preview still skips monthly rates |

**Rate Resolution Precedence:**

1. Custom beats default
2. Dated (effective period) beats indefinite
3. Slot > area > location scope
4. Vehicle-specific beats all vehicles
5. Specific days beat every day
6. Shorter period, higher priority, newest created

### F3. Driver Search, Map and Results Sheet

- Search around current location or a point on the map, no sign-in needed
- **Map pins**: Each shows available count (or Open/Full), net of held/reserved spaces; past stale threshold use warning style (e.g. amber outline); Full listings greyed
- 🟩 **Dense areas cluster**: Cluster bubble shows the **total available slots** of the listings inside it (sum of their counts; Open/Full listings add 0), not the number of listings, via MapLibre GeoJSON clustering with a summed cluster property. Tapping a cluster zooms in until all its pins are visible
- **Results sheet**: Same results as a list in a bottom sheet over the map, partly open by default (peek ~1/3 screen). Dragging the handle expands to nearly full screen or restores; map stays usable at peek
- 🟧 **Sheet title**: The results sheet is titled 'Search Result' (was 'Parking Locations')
- 🟧 **Collapsed sheet shows only its top**: Collapsed, the results sheet shows just the handle, 'Search Result', the summary line and the distance slider, and its height shrinks to fit exactly that (measured; at most half the screen), so the map gets more room. The filters (Vehicle, Rate type, Show Full), the sort chips and the list appear only when the sheet is fully expanded (they appear once it has opened and disappear as it collapses). 🟧 The sort chips and the list are no longer hidden or unmounted when the sheet collapses: they stay rendered just below the collapsed area (clipped off screen), so expanding shows them straight away without re-rendering the rows (the rows re-render only when results, ETAs or the nav app change; replaces the 'appear once it has opened' behaviour). One tap on the handle still expands and collapses on the web. 🟧 The filter dropdowns (Vehicle, Rate type, Show Full) now stay visible when the sheet is collapsed, under the title and summary and above the distance slider; the collapsed height is measured with them included, so it fits title, summary, filters and slider (🟧 the filters are now one row, see Filter row layout). Expanded, the sheet takes 85% of the search screen but its top always stays below the place search box, so the handle can always be tapped to collapse it on short screens (before, on screens around 640 px tall the box covered the handle and the sheet couldn't be collapsed by tapping). The ◎ button keeps 16 dp above the collapsed sheet and is hidden while it's expanded
- 🟧 **Three sheet modes** (replaces Collapsed/Expanded above): **Minimized** is the collapsed view (title, summary, the one-row filters, distance slider; height measured to fit). **Normal** covers 65% of the search screen's height (the area below the header bar). **Maximized** reaches up to 10 px below the header bar, so a 10 px strip of map stays visible; it covers the place search box. Every new search (opening the screen, 'Search this area') puts the sheet in Normal; filter, sort and distance changes keep the current mode. Drag the handle (or anywhere on the sheet) to move between the modes; tapping the handle steps Minimized → Normal → Maximized → Minimized. The sort chips and list stay rendered in every mode. The sheet draws above every map element: the search box, 'Search this area', pins, the location dot and the ◎ button (while place suggestions are open, the search box and its list come to the front so they can be picked). 🟧 The ◎ button sits on the map overlay layer under the sheet, at the right, 16 dp above the top of the Minimized sheet (it uses the measured Minimized height, so it adapts per device, but it does not move while the sheet is dragged). It is visible in Minimized; Normal and Maximized simply cover it (replaces the earlier 'ride 16 dp above the sheet, hide when there is no room' rule and the short-lived 'top right below the search box' placement); it is hidden while place suggestions are open.
- 🟩 **Results summary**: The top of the results sheet shows how many listings were found and their total available slots, e.g. '12 listings · 48 slots available' ('No listings found' when empty, 'Searching…' while loading). Open/Full listings count as listings but add no slots. It updates whenever the results change: filters, distance slider, sort, or 'Search this area'. 🟧 Now reads '12 listings · 48 spots available' ('1 spot' for one)
- **List rows**: Cover photo, count/status, 'updated X ago' (warning style past threshold), starting rate, distance, ETA, rating, Residential/Unverified/Monthly tags
- 🟦 **Rating on cards**: Every result card shows the listing's rating as '★ 4.5 (12)' (average to one decimal, number of reviews); a listing with no reviews shows 'Not rated' in grey
- 🟧 **Navigate on result rows**: Each result row has a small '➤ Navigate' pill at the right of its rating line. It opens directions to that listing in the same map app as the details page's Navigate button (Profile → `preferred_nav_app`: Google Maps, Waze, or the phone default; guests get the phone default), using the row's coordinates (or the listing's `geog` EWKB if a row has none). Tapping it does not open the listing details; tapping anywhere else on the row still does. The pill never wraps and stays inside the card at 320 px wide (the rating text shrinks/ellipsizes instead)
- 🟩 **Stale indicator**: There is no 'Stale' text label anywhere (results list, listing details). A listing past its stale threshold shows only the warning style: the 'updated X ago' time turns amber (and the count badge and map pin turn amber)
- 🟩 **List row layout**: Nothing may run past the card on narrow screens. The status/details line wraps onto a second line when needed and ellipsizes (…) if it is still too long; the name and address are limited to 2 lines with an ellipsis
- **Sort**: distance (nearest first, default), price (starting rate for selected vehicle), rating, ETA, 🟪 'Open slots' (🟧 now 'open spots', all lowercase like the other sort labels; last; was 'Most slots' / 'availability'; most free first, behaviour unchanged)
- **Filters**: vehicle type, saved vehicle, 🟦 rate type (was the Monthly chip), Show Full

## Last-Space Protection (Concurrency)

Two drivers cannot reserve the last space at the same time. Every capacity change goes through one database function that takes a row lock, so concurrent requests run one after another and only the first can take the last space.

### Steps

1. **One function**: `claim_capacity(location, slot?, start, end, kind)` is the ONLY way to take capacity. `request_reservation`, `start_walk_in`, `check_in_reservation`, `set_manual_counts`, `set_slot_status` all call it; app never writes counts directly
2. **Lock first**: Inside one transaction it runs `SELECT ... FOR UPDATE` on the location availability row (count mode) or slot row (slots mode). Second request for same location/slot waits until first commits or rolls back
3. **Check capacity**: Free = capacity − active sessions − overlapping holds and reservations (awaiting_payment, pending_approval, confirmed) − manual Reserved − Unavailable. In slots mode, slot must be available and have no overlapping hold
4. **Create hold or session**: If free ≥ 1, insert reservation/session in same transaction and commit. Otherwise raise 'no_longer_available'; app shows 'This space was just taken' and refreshes results
5. **Excluded immediately**: New hold counts against availability for everyone (search, pins, walk-ins, other reservations) until it is paid, converted to session, cancelled, declined, or hold expires. `release_capacity` runs under same lock
6. **Backstops**: CHECK constraint keeps available ≥ 0 in count mode; in slots mode an exclusion constraint on (slot_id, time range) for active holds makes overlapping insert fail even if code path forgot lock

**Acceptance**: 50 parallel request_reservation calls for one remaining space produce exactly 1 hold and 49 'no_longer_available'; walk-in and reservation racing for last space yield exactly one success; manual Unavailable mark never makes available negative; search never shows held space as available

## Data Model Summary

**Key Tables:**

- `profiles` (extends auth.users): display_name, phone, is_admin, preferred_nav_app
- `operators`: display_name, status, staff_can_waive (default true)
- `operator_members`: operator_id, profile_id, role (owner/manager/staff), location_ids[]
- `locations`: geog Point (PostGIS), address, tracking_mode, capacity, available_count (CHECK ≥ 0), availability_updated_at, stale_after_min, published, verification_status
- `location_photos`: storage_path, is_cover, sort_order
- `areas`, `slots` (Phase 2), `rates`: is_default, rate_type, amounts, effective period, scope, priority
- `vehicles`: driver_id, nickname, plate, vehicle_type, dimensions, is_default
- `parking_sessions`: location_id, driver_id?, plate, vehicle_type, started_at, scheduled_end_at, ended_at, status, rate_snapshot
- `reservations` (Phase 3): location_id, driver_id, vehicle_id, start_at, end_at, status, hold/max_hold expires_at, quote_amount, fee_due_amount, rules_ack_at
- `folios`: operator_id, location_id, session_id?, reservation_id?, status (open/settled)
- `folio_charges`: folio_id, type (parking_fee/additional_fee/adjustment/waiver), amount (negative for waiver), note (required for waiver), added_by, created_at
- `payments`: folio_id, direction (payment/refund), amount, method (cash/gcash/...), recorded_by
- `chat_threads`, `chat_messages`: thread_id, sender_id?, kind (text/image/system), body, image_path, event_type, hidden
- `eta_cache`: origin_cell (~200m grid), location_id, duration_s, distance_m, source (ors/estimate), fetched_at (10-min TTL)
- `notifications`, `reports`, `platform_settings`, `availability_events`, `booking_events`
- 🟩 `attention_triggers`: key, enabled (default true), description — which conditions light the sidebar badge (edited in SQL only); `locations.review_seen_at` (owner saw the verify/reject outcome), `locations.rejected_at/rejected_by/rejection_reason`; `chat_messages.read_at` is now set when the recipient opens the thread

**Money**: Always numeric(12,2) pesos, never floats  
**Balance**: Computed from ledger: charges (waivers are negative) − payments

## Risks and Mitigations

| Risk                                           | Mitigation                                                                                                                                                                                                 |
| ---------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Stale availability erodes trust                | Last update time always shown, warning style past threshold on list and pins, driver reports, one-tap staff console                                                                                        |
| Spaces stay 'occupied' because nobody taps End | Overdue list, repeated reminders, overdue time shown for staff to bill, count freshness warnings                                                                                                           |
| Unpaid reservations tie up spaces              | Operator-set maximum hold from booking with auto-cancel; no-shows released automatically                                                                                                                   |
| No operators yet in Baguio                     | Hands-on onboarding; residential listings widen supply; free for operators in beta                                                                                                                         |
| Fake or misleading listings                    | Unverified badge until admin review, reports, reviews, unpublish/suspend; facility photos help reviewers                                                                                                   |
| Safety of residential hosts with exact pins    | No public phone numbers, optional rules, approval-required option, report 'unsafe', chat instead of public contact                                                                                         |
| Cash handling errors or leakage                | Every cash entry tied to staff member; shift cash summary; voids, amount-due edits and waivers (amount, note, who, when) audited, never deleted                                                            |
| Waivers used to hide pocketed cash             | Required note, waivers listed per staff in shift summary, Operator can restrict waivers to Operator-only (Staff allowed by default)                                                                        |
| Double booking the last space                  | Every capacity change through claim_capacity with SELECT ... FOR UPDATE; CHECK and exclusion constraints as backstops; concurrency tests in CI                                                             |
| Review abuse                                   | One review per account, rate limits, reporting, 'Booked via app', driver reviews only in context                                                                                                           |
| Chat abuse or unsafe images                    | Members-only threads, report message, rate limits, admin hide, EXIF stripping; Operators cannot cold-message drivers                                                                                       |
| Routing quota or outage (ORS free tier)        | ETAs only for visible/top 20, one batched matrix call, 10-min cache, debounce on pan, back-off on rate limits, straight-line estimate fallback; self-host OSRM if volume grows                             |
| ETA accuracy in Baguio traffic                 | Label as drive time without live traffic; Navigate hands off to apps with live traffic                                                                                                                     |
| Map clutter and slow rendering with many pins  | Clustering, virtualized list, pins rendered from one GeoJSON source                                                                                                                                        |
| Data Privacy Act (RA 10173)                    | Privacy notice, minimal location retention, consent, EXIF stripping, driver reviews access-limited, chat images private to thread members; ETA origins rounded to ~200m and kept only in short-lived cache |
